# 修仙世家 · 炼气到化神

一个**零依赖、单文件、双击即玩**的修仙题材挂机游戏。从一介凡人立族开始，一路修到化神。

所有数值、规则、界面都写在一个 HTML 里 —— 没有构建步骤对玩家可见，不需要服务器，不需要联网。

> **直接玩**：下载 [`game.html`](game.html) 用浏览器打开即可。
> 存档在浏览器 localStorage（键 `xiuxian-family/save/v1`），**换浏览器或清缓存会丢档**。

---

## 这个游戏特别在哪

**每一笔银两的支出，都要先答对一道六级单词题。**

建造、研习、通商、炼丹、冲关——全部走答题门槛。答错则操作失败（普通难度退还材料，地狱难度材料没收）。
默认题库是内置的六级词库，也可以导入自定义题库（比如把课件、讲义变成题目）。

所以它既是挂机游戏，也是一个**能真正用起来的背单词工具**：错题本会记录错词，
按错次加权提高重现率，直到你掌握。**答题记录跨周目保留** —— 重开一世不会清空你的学习进度。

## 玩法概览

**两条时间线交织**：

| 阶段 | 内容 |
|---|---|
| **凡尘篇** | 田地 / 地产 / 房产 / 钱庄 / 演武台 / 商队驿站。养人口、攒银两、收集秘闻 |
| **仙途篇** | 灵池、灵脉矿场、宗门、洞天、攻伐；灵根、炼丹、炼器、炼符、地图、百科、轮回 |

**境界**：凡人 → 炼气（一~九层）→ 筑基 → 金丹 → 元婴 → 化神，共 25 级。
小境界自动晋升，**跨大境界必须主动冲关**——有公开的成功率、材料代价和失败惩罚。

一周目约 **44 小时**（`REALM_XP_RATE` 是全局节奏总旋钮）。

**周目与金手指**：修至化神可重入轮回，用轮回点解锁**改变规则**的金手指——
比如韩立的**掌天瓶**（药材产出 ×2.5，代价是全族修炼 −10%）。每一件都必带代价。

## 工程结构

```
xiuxian-qi/
├─ game.html            ← 构建产物（647 KB，唯一交付物，别手改）
├─ src/                 ← 分区块源码，39 个文件
│  ├─ _manifest.json    ← 区块拼接顺序（唯一真相源）
│  ├─ _shell-head.html  ← HTML 骨架 + 全部 CSS
│  ├─ core/             ← config / state / engine / formulas / quiz / save / format
│  ├─ data/             ← 纯数据表：buildings techs trade words pills cultivators
│  │                       manuals realms roots map alchemy forge runes codex reincarnation
│  ├─ systems/          ← 规则：cultivation manuals manual-drops exploration alchemy
│  │                       forge runes breakthrough roots reincarnation codex progression
│  ├─ ui/               ← app.js（界面）、quiz-view.js（答题弹窗）
│  └─ main.js           ← 入口、事件绑定、调试出口
├─ scripts/
│  ├─ build.mjs         ← src/ → game.html
│  ├─ smoke.mjs         ← 533 项断言（用 DOM 垫片真跑一遍）
│  ├─ dom-shim.mjs      ← 最小 DOM 实现
│  └─ extract.mjs       ← 单文件 → src/ 的一次性拆分工具
└─ docs/                ← 设计文档与截图
```

**分层约定**：`ui → systems → data → core`。数值住在 `data/`，规则住在 `systems/`，
`data/` 里不写 `if`，`systems/` 里不写魔法数字。

**改游戏的方式**：改 `src/` 里的对应区块 → 跑 `npm run build` → 得到新的 `game.html`。

```bash
npm run build     # src/ → game.html
npm run check     # 校验 game.html 与 src/ 逐字节一致
npm run smoke     # 533 项断言
npm test          # check + smoke
```

## 几条设计原则

1. **每个系统都要有负面对价。** 演武台折人、商路死人、好灵根留不住（宗门出价挖走）、
   符箓有保质期、法器有耐久、金手指必带代价。白送的东西会让选择失去意义。
2. **概率与代价必须公开。** 冲关成功率、洞天生还率、攻伐胜算、炼丹成功率——
   全部写在按钮旁边。玩家不该对着黑箱做决策。
3. **随机只用来创造机会，不用来夺走资产。** 领地叛离是**确定性计时器**（界面显示民怨百分比），
   不是随机事件。随机没收玩家已有的东西只会让人恼火。
4. **百科聚合，不重抄。** 背景文字写在各张数据表自己身上，百科直接引用。
   测试里有一条专门盯着这件事——改表不改百科就会挂。
