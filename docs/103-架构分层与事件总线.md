# 架构分层与事件总线（第 1 轮）

> 本文回答一个问题：**用户建议的七阶段重构，哪些已经做了、哪些没做、按什么顺序做。**
> 每一条都对着代码核过，不是设计愿景。

| 用户阶段 | 现状 | 证据 |

## 二、目标分层

```
        UI（只做渲染与派发）
         │  data-action / data-immortal-action
         ↓
      Action 层（校验 + 调系统 + 反馈）
         │
         ↓
    Game Systems（业务规则，不碰 DOM）
         │            ↑
         ↓            │ EventBus（通知，单向）
       State          │
         │            │
         ↓            │
     Save / Load ─────┘
```

三条不许破的规矩：

1. **UI 不许直接改 state** —— 一律经 Action 层（现状已满足）。
2. **系统之间不许横向调用** —— 广播事件，谁关心谁订阅（第 1 轮已建立）。
3. **顺序敏感的记账留在系统内部**，不要搬进订阅者 —— 否则"谁先谁后"变成隐式契约。

## 三、第 1 轮做了什么

### 3.1 `src/core/eventBus.js`

纯内存，不碰 state、不碰 DOM、不碰计时器。三条硬约束：

| 约束 | 为什么 |
|---|---|
| **订阅者抛错绝不影响 emit 的调用方** | 一个写坏的成就系统不能把整帧 tick 炸掉。断言里真的让订阅者抛错来验 |
| **重入深度上限 8 层** | 订阅者里再 emit 同一事件会无声死循环把页面卡死 |
| **事件只做通知** | 顺序敏感的记账留在系统内，别搬进订阅者 |

### 3.2 `src/systems/chronicle.js`（族谱以订阅者身份存在）

把「修士入册」的日志**从系统里搬进订阅者**：

```js
// 旧（systems/cultivation.js）：修士系统必须知道族谱存在
if (!silent) { pushLog(state, `…成为家族第 N 位炼气修士。`, 'cultivate', null, now); }

// 新：只广播
emitEvent(GAME_EVENTS.CULTIVATOR_JOINED, { state, name, qi, innate, now });
```

⚠ **文案与位置逐字照搬**：emit 仍在原来 `pushLog` 的同一行位置，订阅者同步执行
⇒ 日志相对顺序、`pushLog` 的「同 key 4 秒内合并计数」行为都不变。
断言直接比对 `state.log[0].text` 与旧文案是否**完全相等**。

### 3.3 事件清单（payload 契约）

| 事件 | payload | 广播点 |
|---|---|---|
| `CULTIVATOR_JOINED` | `{state,name,qi,innate,now}` | `systems/cultivation.js` 的 `addCultivator` |
| `PILL_CRAFTED` | `{state,recipeId,name,n,prof,profUp}` | `systems/alchemy.js` 炼成 |
| `PILL_CRAFT_FAILED` | `{state,recipeId,name,rate}` | `systems/alchemy.js` 炼废 |

⚠ 事件名一律用 `GAME_EVENTS` 常量，**不许写裸字符串** —— 拼错了不报错，只是不触发。

## 四、后续轮次（改一处、验一处）

| 轮次 | 内容 | 风险 | 为什么排这个位置 |
|---|---|---|---|
| 2 | 存档 `version` + 迁移骨架 | 低 | **必须早于轮 5**：没有迁移能力就改 state 结构 = 全体老玩家丢档 |
| 3 | `engine/` 层拆分（tick / offline / simulation 独立） | 低 | 纯搬迁，`core/engine.js` 778 行是最容易拆的 |
| 4 | Action 层拆分（`main.js` 1625 → `ui/actions/*`） | 中 | 业务规则下沉到 systems，让 Action 只做"校验+调用+反馈" |
| 5 | **state 分组 + 迁移**（`silver` → `economy.silver`） | 高 | 有了轮 2 的迁移框架才敢做；必须有"旧档读进来仍能玩"的断言 |
| 6 | `ui/panels/*`（`app.js` 2052 拆成一页一文件） | 中 | 纯渲染搬迁，最后做 |

**顺序上唯一必须纠正的一处**：用户的阶段 6（存档迁移）排在阶段 2（State 重做）**之后**是危险的 ——
他自己举的例子（v1 `pill:10` → v2 `alchemy.pills:10`）恰恰说明：**先有迁移，才敢改结构**。
