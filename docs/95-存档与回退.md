# 95 · 存档与回退

> 本文档由主策（captain）建立。目的：**任何时刻都能把代码退回任意一个已知状态**。
> 建立于 2026-10-11，起因是程序负责人在 t3 连续工作约一小时后，工作区已积累 26+ 个**未提交**的改动文件 —— 那是一段没有退路的时间。

## 一、为什么 git 本身不够

`git commit` 只能保护**提交过**的状态。而这个项目由多个 agent 成员并行改代码，一份工作常常要跨几十分钟才提交一次：

- 成员改崩 / 覆盖错文件 → 没有退路
- 进程被掐、会话崩溃 → 未提交的改动全丢
- 想比较"半小时前是什么样" → 无从比较

`git stash` 和 `git commit` 都**不适合**在成员工作时运行：前者会改动工作区（成员正在编辑的文件会被切走），后者会污染分支历史（把半成品提交进 `main`）。

## 二、原理：临时 git 索引

`scripts/snapshot.mjs` 用 `GIT_INDEX_FILE` 指向一个**临时索引文件**，把工作区写成一棵 tree，再 `commit-tree` 生成提交对象并打标签 `ckpt/<时间戳>`。

```
GIT_INDEX_FILE=D:\harness\.snapshots\idx-xxx  git add -A
                                              git write-tree
                                              git commit-tree <tree> -p HEAD -m "..."
                                              git tag ckpt/<时间戳> <commit>
```

**全程不碰工作区文件、不碰真实索引、不移动 HEAD。** 所以它可以在成员正在改代码的时候安全运行 —— 这是它唯一存在的理由。

快照对象存在 `.git` 里（由标签引用，不会被 `gc` 回收），临时索引文件放在**仓库之外**的 `D:\harness\.snapshots\`，不会被 `git add` 扫到。

## 三、用法

```powershell
cd D:\harness\xiuxian-qi

# 打一个快照
node scripts/snapshot.mjs --note "t3 实现到一半"

# 看有哪些快照
node scripts/snapshot.mjs --list
node scripts/rollback.mjs --list          # 等价

# 演练：只显示会改哪些文件，不落盘（默认行为）
node scripts/rollback.mjs ckpt/20261011-184753

# 真正恢复（会先自动快照当前状态，所以这一步本身也可回退）
node scripts/rollback.mjs ckpt/20261011-184753 --apply

# 只恢复一个文件
node scripts/rollback.mjs ckpt/20261011-184753 --apply --file src/core/save.js

# 跳过交互确认（给脚本/agent 用）
node scripts/rollback.mjs ckpt/20261011-184753 --apply --yes
```

## 四、三条安全设计（重要）

1. **回退前先自动快照当前状态** —— 于是"回退"这个动作**本身也是可回退的**。这是整个系统里最重要的一条：没有它，回退就是又一次不可逆操作。
2. **默认只演练、不落盘**。要真改必须显式加 `--apply`。
3. **只恢复快照里有的文件，绝不删除**任何当前文件。快照之后新增的文件会被**列出来提醒**，但不会被删掉。

## 五、自动化

| 自动化 | 频率 | 权限 | 职责 |
|---|---|---|---|
| **存档守护 · 每 20 分钟自动快照** | 20 分钟 | workspace-write | 只跑 `scripts/snapshot.mjs`，其它 git 操作一律禁止 |
| 项目监督员 · 每 30 分钟进展巡检 | 30 分钟 | read-only | 报告进展 / 死机 / git 积压，**不修改任何东西** |

脚本自己保留**最近 40 个**快照，更老的标签自动裁剪。

## 六、与 git 的关系

| 想要什么 | 用什么 |
|---|---|
| 保护**未提交**的工作（日常） | `snapshot.mjs` |
| 回退**工作区**到某快照 | `rollback.mjs <tag> --apply` |
| 回退**提交历史**（丢弃 HEAD 之后的提交） | `git reset --hard <tag>` ⚠️ 连提交一起丢，慎用 |
| 正常交付 | `scripts/ship.mjs`（构建→check→smoke→commit→push） |

`ckpt/*` 标签是**本地**的，不随 `git push` 上传。它们的作用是本地容灾，不是发布手段。

## 七、给成员的操作纪律

- **动手改多个文件之前**，先 `node scripts/snapshot.mjs --note "<你要做什么>"`。代价是几百毫秒。
- **不要用 `git stash`** —— 会把别人正在编辑的文件一起切走。
- **不要用 `git reset --hard`** —— 会丢弃提交；要回退工作区用 `rollback.mjs`。
- **不要 `git add -A`** —— 多 agent 共用工作区时会扫走别人的半成品（见全局规则 R18/R21）。
