# 100 · 资源清单与解锁节奏

> 本文回答一个问题：**游戏里所有「玩家看得见的量」分别是什么、属于哪一类、什么时候才该让玩家看见。**
>
> 用户原话（需求源头）：
> 「我发现游戏内部没有规定变量的属性，银两是银两，人口是人口，这样是不对的，比如银两的属性是资源，应该和后续的其他资源归为一类。」
>
> 本文只做**归类与节奏**（清单 + 门控 + 未解锁表现），不改数值、不写实现。
> 实现阶段的接口建议放在 §附录 B（给 t2 的输入）。
>
> 引用一律用**符号名**（表名 / 函数名 / 字段路径），不写行号 —— 行号会漂，符号名能 grep。
> 全部清单**靠逐表读代码得到**，不靠记忆；出处列即证据。

---

## 零、一句话结论

现在的代码里已经有 **78 条玩家可见的台账条目**（把 4 种药材 / 4 种矿料 / 4 种符料 /
8 个丹方 / 9 件法器 / 4 张符箓按种类展开，就是 **110 多个具体资源**），
但它们散落在 `createState()` 的顶层字段、`derive()` 的派生值、
`cultivation.*` 的三条生产线子对象里；**「是不是一类东西」这件事在代码里没有任何表达** ——
银两是 `state.silver`，灵石是 `state.spiritStones`，药材是 `cultivation.alchemy.herbs[k]`，
三者形状不同、读写入口不同，谁也不知道它们其实是同一类。

本文给出：

1. **六个类别**，其中「货币 + 材料」统称**资源**（用户要的那一层）；
2. 每个量的**符号路径 + 出处 + 归类理由**；
3. 每个**资源**的**解锁条件**与**未解锁时的界面表现**三种口径（藏 / 灰 / ？）；
4. 一张**明确不该有解锁状态**的白名单清单（死亡率、世界钟、解锁标记本身……），附理由。

## 一、类别体系

| 代号 | 类别 | 定义（一句话判据） | 是否「资源」 |
|---|---|---|---|
| **C** | **货币** Currency | 能**付出去**换别的东西、本身不再被加工的量 | ✅ 是（资源） |
| **M** | **材料** Material | 产地固定、会被**消耗去合成/升级**的量（含成品存货：丹/器/符） | ✅ 是（资源） |
| **P** | **人口** Population | 以「人 / 人次」为单位的量，是**劳力与产出基数** | ❌ 否（但同样是供给侧资源） |
| **G** | **进度与等级** Progress & Level | 单向只增、或表征「走到哪一步」的量（含各类**容量**） | ❌ 否 |
| **X** | **属性与倍率** Modifier | 描述**世界规则与乘数**的量：速率、概率、倍率、修正 | ❌ 否 |
| **F** | **解锁标记** Flag | 本身就是**门控判据**的量（`unlocked` / `status` / `visible`） | ❌ 否 |

两条补充子类（都在 **M** 之下，因为性质相同）：

- **M1 原料**：药材 / 矿料 / 符料 —— 只被消耗，不被显示为「装备」；
- **M2 成品存货**：丹药 / 法器（含耐久）/ 符箓（含保质期）/ 人丹 —— 有存量与保质/磨损语义。

**为什么货币与材料要合成「资源」一大类**：
两者的形状完全同构 —— 都有**存量**（数字）、都有**产出源**（产率）、都有**消耗口**，
而且都在「资源条」上被显示成 `当前 / 上限`。银两 ↔ 灵石 ↔ 药材 ↔ 矿料 ↔ 符料
在架构上应当能被同一套代码读出来（`path(state)`、`rate(state)`、`cap(state)`），
今天它们各自硬编码在 UI 的 `PAGE_RES` / `main.js` 的模板里，这正是用户说的「没有规定变量的属性」。

## 二、全量台账

> 读法：**符号路径**是唯一读法入口（有的今天只能从 `derive()` 拿，已在出处列写明）。
> 「门控」= 是否需要一个解锁条件才能被玩家看见。

### 2.1 C 货币（资源·货币类）

| 显示名 | 符号路径 | 出处（符号） | 归类理由 | 解锁节奏（门控 → 表现） |
|---|---|---|---|---|
| 银两 | `state.silver` / 上限 `derive().silverCap` | `core/state.js` `createState`；`core/config.js` `BASE.silver`；`core/formulas.js` `derive` | 唯一能付建筑/科技/施粥的钱，本身不再被加工 ⇒ 货币 | **开局即见**（`BASE.silver = 100`）。显示为 `银两 N / 上限`（`ui/app.js` 的 `PAGE_RES.home`） |
| 灵石 | `state.spiritStones` | `core/state.js`；`derive().stones` | 仙道侧唯一硬通货（丹/器/符/科技/冲关都吃）⇒ 货币。小数（`STONE_DECIMALS = 1`） | 门控：**`derive().marketUnlocked`**（`secrets ≥ SECRET_UNLOCK`）。未解锁时**藏**：仙途页整体不可见（`pageVisible('immortal')` → `immortalAccessible()`），资源条里根本没有灵石这一格 |
| 秘闻（累计） | `state.secrets`（`SECRETS` 下标集合） | `core/state.js`；`derive().secretCount / secretGoal` | **是解锁凭证**（门槛读它、商品解锁读它），口径与「可消耗的线索」不同 ⇒ 归货币类的「凭证货币」 | 门控：通商页资源条里一格 `秘闻 N / 10`（`PAGE_RES.trade`）。**开局即见**（通商页开局可见），因为它是「怎么才能开仙途」的唯一线索 |
| 秘闻（已花） | `state.secretsUsed` | `core/state.js`；`systems/markets.js` `secretsAvailable` | 与上式同族的记账半边（累计 − 已花 = 可用） | 同上（显示在坊市面板的 `秘闻 可用 A / 累计 B（已花 C）` 一行） |
| 秘闻线索（可用） | `cultivation.clues` / 小数池 `cultivation.cluePool` | `core/state.js`；`systems/cultivation.js` `progressCultivators` | **会被消耗**（洞天入场、冲关门槛）⇒ 与 `secrets` 是两件事，属货币类 | 门控：**秘境分块**（`immortalBlockVisible('cave')` 不拦；但仙途页本身要 `immortalAccessible()`）。显示为 `可用线索 N 条`；未解锁时**藏**（整个仙途页不在） |
| 轮回点 | `meta.points`（`metaOf(state)`） | `core/state.js`；`systems/reincarnation.js` | 跨周目保留、只能花在金手指上 ⇒ 跨局货币 | 门控：**`pageVisible('cycle')`**（`reincarnationProgress().canEnd` 即 `REINCARNATION_MIN_INDEX = 22` 化神初期，或 `cleared > 0` / `unlocked.length > 0` / `cycle > 1`）。未解锁时**藏**整个页签 |

**⚠ 归类发现 1（必须记下）**：`state.secrets`（累计秘闻）与 `cultivation.clues`（可用线索）
在文案上都叫「秘闻」，但一个是**只增不减的解锁凭证**、一个是**会被扣掉的消耗品**。
`systems/markets.js` 的头注已经写明「一切旧门槛一律读累计」——
这条规则必须写进资源注册表（`secrets` 的门控读法固定为累计），否则后来人很容易改成读可用数，
那会让「花秘闻解锁商品」把已经打开的门又关上。

## 三、解锁节奏（时间线）

一句话：**门控要跟着玩家「有事可做」的那一刻打开，宁可晚一点，也不要一开局摆出全部栏目。**
（这条原则已经写死在 `systems/progression.js` 的头注里，本文把它推广到资源上。）

```
开局
├─ 即见：银两(100) / 人口(10) / 建筑容量(6) / 容纳(20) / 岁入 / 出生率 / 死亡率 / 净增长
│        田地×1 / 通商页 / 治学页 / 百科页 / 格物页
├─ 研习 realestate ─────→ 地产（+6 建筑容量/座）
├─ 研习 architecture ───→ 房产（+40 容纳/座，全局造价 +2%/座）
├─ 研习 finance ────────→ 钱庄（+8000 银两上限/座）
├─ 研习 expansion ──────→ 演武台（地产折扣↑、死亡率 +0.0006/座）
├─ 研习 trade ──────────→ 商队驿站 → 商队位 +1/座 → 通商页出现「商队 N / M」
├─ 商路带回秘闻 ≥ 10 ───→ 【云深谷坊市开放】→ 银两→灵石兑换（10 万两 → 0.5 灵石）
│                          → 「仙途」页出现（判据 immortalAccessible：**买得起祛障丹就必须能看见入口**）
├─ 研习 quzhang（需 10 秘闻）─→ 祛障丹可服（1 灵石 / 25% 成率）
├─ 第一名修士 ──────────→ 名册 / 修为 / 境界 / 天赋 / 灵根 / 各职责人数
│                          → 境界仪表盘第 1 格「行气 · 炼气」
├─ 派差事（仅炼气 1–9 层）→ 线索（可消耗）/ 有去无回
├─ 洞天（花灵石 + 线索）→ 已抵达节点 / 功法掉落
├─ 攻下势力城 ─────────→ 已占领 + 【必须派镇守】→ 领地赋税 / 药材 / 矿料 / 符料
│                          + 青木集市（1 城）/ 黑石城坊（2 城）/ 万象楼（3 城）
├─ 仙道科技 lingtian ──→ 药圃（城产青灵草）；xuanhu → 矿寮 + 纸坊
├─ 有领地或开过炉 ──────→ 【丹房 / 器坊 / 符房】三个分块（immortalBlockVisible）
├─ 秘闻 ≥ 15 ──────────→ 寻龙尺 → 灵脉（阶 + 储量）→ 矿场 → 矿工派工
├─ 坊市买「灵池蓝图」──→ 灵池（0–10 座，0.00013 灵石/座/秒）
├─ 主修血煞一脉 ────────→ 人丹分块（献祭 5 凡人 + 2 灵石，道心 −8）
├─ 炼气九层冲关 ────────→ 择地筑基 → 道基（地气/品阶/词条）→ 仪表盘换「道基 · 筑基」
├─ 金丹期 ─────────────→ 丹图（丹纹 / 品阶 / 本层余 N 次）
├─ 元婴期 ─────────────→ 圣胎（稳固 0–100 / 出窍 / 回体）
├─ 化神三层 ────────────→ 天劫准备面板（减免来源清单 + 缺口 N 点）
└─ 化神初期（index 22）─→ 【轮回页出现】→ 轮回点 → 金手指（4 件，2 个携带位）
```

**三条节奏铁律**（从现有代码里归纳，建议写进实现）：

1. **一旦可见就不要让它消失**（`systems/progression.js` 的 `immortalAccessible` 注释原文约定）。
   例外只有重开与轮回。
2. **门控判据必须问「他现在有没有事可做」，不是「他有没有某个东西」** ——
   仙途页曾经因为判 `qi > 0` 而自锁（买祛障丹的入口在仙途页里，没修士就看不见仙途页，
   于是永远拿不到第一个修士）。**资源门控必须用「入口可达」而不是「已有量 > 0」**。
3. **未解锁的资源不许在资源条上留下剪影**：一旦出现 `？？？` 的格子，玩家就把它当成
   「有东西我不知道怎么拿」。所以**未解锁的资源一律不占格子**，只在「如何解锁」的引导文案里出现。

## 四、不该有解锁状态的量（白名单）

用户问得对的地方在于：**不是所有量都该被门控。** 下面这些必须**始终可见**，
理由分三类：**规则透明**（藏起来就是隐藏公式）、**惩罚反馈**（藏起来等于隐藏代价）、
**门控自身**（自我门控会死锁）。

| 量 | 类别 | 为何不门控 |
|---|---|---|
| `deathRate` 死亡率（含 `crowdDeath` / `expandDeath` / `laborDeath`） | X | **惩罚要可见**。玩家看到「演武台折去 X/秒」「拥挤多出 Y/秒」才会做取舍；藏掉它就等于把负面对价变成暗扣，违反 `docs/00-整体策划.md` 的不做隐藏公式原则 |
| `birthRate` / `netRate` / `netPerSec` / `populationMood` | X | 与死亡率成对，是玩家判断「这块地还能不能撑住」的唯一刻度 |
| `crowdRatio` / `crowdOver` | X | 拥挤惩罚的**预警**；`CROWD.threshold = 0.75` 触发线必须在看见之前就可见 |
| `unrest` 民怨 | G/X | 涨满即失去领地。**倒计时不能藏**，否则叛离像随机事件 |
| `silverPerSec` / `silverCap` / `buildingCap` / `housingCap` | X/G | 速率与配额是**决策依据**（「还要多久买得起」），且它们是凡人模块的地基 |
| `clock.year` 世界钟 | G | 它是**内部时钟**：1 游戏小时 = 25 年，只经 `lifeSpanText` 折算成「寿 X，余 Y」出现。玩家不需要也不该看见裸年号 —— 它没有「获得」的语义 |
| `stats.*`（`silverEarned` / `silverWasted` / `silverFromSales` / `playSeconds`） | — | **纯内部记账**，当前 UI 一处都没读；不要为它造门控，也不要为了显示而门控 |
| `tradeRuns` / `marketSellCount` / `exchangeCount` | — | 统计计数。`exchangeCount` 只在坊市说明里以「已兑 N 笔」出现，且**兑换已无上限**（`marketExchangeLimit` 返回 `Infinity`），所以它不是资源 |
| `quiz.lostStones` / `customQuizStats` / `customWrongBooks` | — | 治学侧的内部账，属于学习记录而非游戏资源 |
| `morality` 道心**本身的可见性** | X | 它确实有「分块（仙途页内）」这层门控，但**一旦仙途页出现，道心就必须一直可见** —— 它是档位轴，藏起来会让 `taxMult` 的跳变无法解释 |
| `generation` 世家世代 | G | 顶栏身份信息，开局即见 |
| `pageVisible` / `techStatus` / `derive().unlocked` / `codexEntrySeen` | F | **门控的实现不能门控自己** —— 自我门控必然死锁（仙途自锁就是这么发生的） |
| `population` / `person.xp` / `person.realmIndex` / `person.talent` / `person.root` | P/G | 连续量 + 创角即定：没有「解锁」这个语义；人口还是银两产出的唯一解释 |

## 五、未解锁时的界面表现（三种口径）

| 口径 | 语义 | 现有先例（可直接沿用） |
|---|---|---|
| **藏**（hide） | 整块 / 整格**根本不渲染**（DOM 里不存在） | `pageVisible`（页签）、`immortalBlockVisible`（丹房/器坊/符房/人丹）、`dashboardVisible`（境界仪表按格切换）、`techVisible`（未达前置的科技不进列表） |
| **灰**（dim） | 渲染出来，但 `disabled` + 一句**可执行的**原因 | 建筑卡 `is-locked` + `须研习「<科技名>」`；坊市商品 `需 N 条秘闻解锁`；丹方/法器/符箓 `is-locked` + `map-warn` 缺什么；地图节点 `与此地不相邻 · 需先打通沿途`；通商「须研习「商路」并建起驿站」 |
| **？**（mask） | 只显示「有这东西」+ 获取线索，不显示数值 | **唯一现成先例**：`systems/codex.js` + `ui/app.js` 的 `renderCodexLocked` → 标题 `？？？` + `e.hint`；由 `ui.codexShowLocked` 控制是否展示占位 |

**建议的资源口径（待主策与 t2 确认）**：

- **资源条（`PAGE_RES` / 主策说的「每一页自己的资源条」）**：走 **藏**。
  未解锁的资源不占格子 —— 因为占位格子会被读成「有东西我不知道怎么拿」（§三 铁律 3）。
- **资源的生产/消耗面板（丹房、器坊、符房、矿场）**：走 **灰**。
  玩家已经在做这件事了，缺什么必须写清（这是「不做隐藏公式」的落地形态）。
- **百科与图鉴类**：走 **？**（已有实现，不改）。
- **引导（`GUIDE_STEPS` / `overview`）**：未解锁资源**只在这里出现名字**，
  并且必须带「怎么拿」的一句话（例：`集齐 10 条秘闻，才能摸到云深谷坊市`）。

## 六、数值解析推导（逐个资源的关键式）

> 归类之外，本节把「显示出来的数字是怎么来的」写清楚 —— 门控判据要引用同一批符号，
> 否则会出现「界面写的是这个、结算用的是那个」。

**货币类**

- 岁入（银两/秒）`silverPerSec`
  = `population × BASE.silverPerPop(0.12) × (1 + fx.incomeMult + marketWorkerBonus) × (1 + cultivationBonuses.laborMult)`
  - `marketWorkerBonus = cityMarketWorkers(state) × CITY_MARKET_YIELD_PER_WORKER(0.0015)`（人不够时按需求分摊，见 `cityWorkersOf`）
  - `laborMult = min(2, workUnits × 0.08)`，`workUnits` = 劳作职责者「大档内层号 ×(1+功法 labor)」之和
- 银两上限 `silverCap = round((BASE.silverCap(3000) + bank × BANK_CAPACITY(8000)) × (1 + fx.vaultMult))`
  - 乘数在括号外：库房放大「已经堆了多少间钱庄」
- 灵石兑率 `marketExchangeQuote`：`100000 银两 → 0.5 × (1 + fx.tradeStoneMult) 灵石`
  - 反向 `marketSellQuote`：`× MARKET_SELL_RATIO(0.8)` ⇒ 任一回路**严格亏 20%**，与笔数、与科技都无关
  - **兑换无总量上限**（`marketExchangeLimit` → `Infinity`，修用户实机死锁）；旧口径 `marketExchangeLegacyLimit = 12 + 4×相关科技数` 仅存档引用
- 秘闻产出：商路每趟 `tradeSecretChance = route.secretChance + fx.secretChance + exploreTradeBonus`（`exploreTradeBonus = min(0.50, exploreUnits × 0.02)`）；另有 `explorePerSec = exploreUnits/9600 + fx.explorePerSecFlat` 按秒判定
- 线索产出的**两条腿**：① 差事（每人 `ERRAND_CLUE_PER_SEC = 2.5e-5`/秒）；② 科技 `cluePerSecFlat` 走 `cluePool` 小数池（`tanxue +2e-4`、`jiexu +4e-4` /秒），每满 1 才 +1 条

**材料类**

- 领地材料（每秒）= `node.<herb|ore|rune Yield> × metaMaterialMult × (1 + fx.territoryYieldMult) × (1 + earthQiLandBonus)`
  - ⚠ **只有「有效镇守」才产出**：`mapIsPacified` 要求 `mapHoldStrength + nascentWardPower ≥ mapHoldPowerFor`
- 城产原料（每秒）= `cityWorkersOf(buildingId) × CITY_<HERB|ORE|RUNE>_PER_SEC × cityMaterialMult`
  - `cityWorkersOf` 在人口不足时按「名义需求」分摊 ⇒ **作坊多而人少会摊薄**
- 赋税(灵石/秒) = `node.yield × (1 + fx.territoryYieldMult) × (1 + earthQiLandBonus) × metaStoneMult × moralityTaxMult`
  - ⚠ **现状缺口**：地图面板那一行 `赋税 Y 灵石/时` 用的是 `node.yield × 3600`，
    **没过** `territoryYieldMult / earthQiLandBonus / moralityTaxMult`；而结算（`advanceTerritories`）是过的。
    资源归类时应把「同一资源必须只有一个计算入口」写成硬约束。
- 民怨涨落：涨 `MAP_UNREST_PER_SEC = 1/900`（15 分钟满）→ 满则叛离；降 `MAP_CALM_PER_SEC = 1/300`（5 分钟清空），出窍元婴在场再 ×`NASCENT_CALM_MULT(3)`
- 熟练度：0–10，每级 `+STEP(0.015)` = **+1.5% 成功率**；上限 `RATE_MAX 0.98 / RATE_MIN 0.05`

**人口类**

- 出生率 = `(BASE.birthRate(0.010) + fx.birthFlat + field × FIELD_BIRTH(0.0012) × (1 + fx.fieldBonus)) × schoolBirthMult`
- 死亡率 = `(BASE.deathRate(0.010) + crowdDeath + expandDeath + laborDeath + fx.deathFlat) × schoolDeathMult`
  - `crowdDeath = CROWD.k(0.014) × crowdOver²`，`crowdOver = max(0, (crowdRatio − 0.75)/0.25)`
  - `expandDeath = arena × 0.0006 + caravan × 0.0008`
  - `laborDeath = laborWorkers × CITY_LABOR_DEATH(1e-7)`
- 净增/秒 = `population × (birthRate − deathRate)`

**进度与等级 / 属性**

- 战力：`totalPower = population × 0.1 + corePower + guardBonus`
  - `corePower` 逐人累加 `realmPower(层号) × (1 + 功法power + 法器power + 流派power + fx.familyPowerMult) × 丹品power倍率`
  - `guardBonus = Σ(guard 岗位者 base × 0.5)`（`CULTIVATOR_JOBS.guard` 承诺的 +50%）
- 建筑容量 = `BASE.buildingCap(6) + estate × ESTATE_SLOTS(6)`；容纳 = `BASE.housing(20) + house × HOUSE_CAPACITY(40)`
- 世界钟：`clock.year += (游戏秒/3600) × YEARS_PER_GAME_HOUR(25)`；**离线不推**
- 轮回点 = `POINT_BASE(1) + held × PER_HOLD(1) + ⌊manuals / PER_MANUALS(5)⌋ + ⌊(top − 22)/PER_REALM(1)⌋`

## 七、现状缺口（归类之外，但会直接影响「解锁体系」的正确性）

归类的意义之一是**把散落的门控集中起来**。盘点时发现下面这些门控数字**没有单一出处**，
实现阶段应一并收进资源注册表（否则会出现「界面与结算读的不是同一个门槛」）：

| 缺口 | 现状 | 建议 |
|---|---|---|
| 寻龙尺门槛「秘闻 ≥ 15」 | 字面量 `15` 同时出现在 `src/main.js` 的面板与 `systems/immortal-actions.js` 的守卫里（两处） | 提到 `core/config.js`（例如 `COMPASS_SECRET_GATE`）或进注册表 |

| 灵池上限 `10 座` / 矿脉上限 `20 处` / 矿工上限 `1000 人` | 字面量（`immortal-actions.js` 与 `main.js` 各写一次） | 同上 |

## 附录 B · 给实现阶段（t2）的接口约定（建议，未实现）

归类要能被代码说清楚，最小的一份单表就够。建议形状（**字段名可改，语义别改**）：

```js
// src/data/resources.js —— 资源台账（唯一真相）
const RESOURCES = [
  {
    id: 'silver',                     // 稳定 id，存档/断言用
    name: '银两',
    kind: 'currency',                 // currency | material | population | progress | modifier | flag
    group: 'resource',                // resource（货币+材料）| world（人口/进度/属性）| gate（解锁标记）
    path: (s, d) => s.silver,         // ★ 唯一读法入口（禁止 UI 自己算）
    rate: (s, d) => d.silverPerSec,   // 可选：产率
    cap:  (s, d) => d.silverCap,      // 可选：上限
    gate: null,                       // null = 不门控；否则 { kind:'tech'|'realm'|'held'|'secrets'|'building', value }
    lockedUi: 'hide',                 // hide | dim | mask
    hint: null,                       // 未解锁时告诉玩家怎么拿（与 GUIDE_STEPS 同源）
    dev: 'unlimited',                 // 开发者模式语义：unlimited | none（t3 用）
  },
  // …
];
```

三条硬约束（写进实现与测试）：

1. **门控判据只有一个来源**：`gate` 由注册表求值，UI 不许自己写 `if (state.techs.includes(...))`。
2. **`lockedUi` 必须显式声明**，不允许「默认藏」—— 默认值会让人漏项。
3. **`dev: 'unlimited'` 只对 `kind ∈ {currency, material}` 有意义**（开发者模式「已解锁资源无限」），
   对 `population / progress / modifier / flag` 一律 `none` —— 否则 `population = ∞` 会把死亡率的
   拥挤项炸成 `∞²`，`realmIndex = ∞` 会让境界表越界。这条是 t3 的输入。

## 附录 C · 复核方式（可机械验证）

实现之后，下面几条应当能被冒烟测试钉住（与既有 `scripts/smoke.mjs` 风格一致）：

1. `RESOURCES` 里每个 `id` 唯一；每个 `path(s, d)` 都能在**新开局**与**满进度**两种状态下返回数字而不抛错。
2. 每个 `gate` 都能在**某个可达状态**下为真（不存在永远解不开的解锁条件）。
3. 每个 `kind ∈ {currency, material}` 的项都有 `rate` 或明确的「非产出型」标记（丹/器/符成品可无 `rate`）。
4. `lockedUi === 'hide'` 的资源，其 `id` **不得**出现在任何 `PAGE_RES` 表里。
5. 每条 `hint` 都是非空中文（未解锁时必须能告诉玩家怎么拿）。
6. **同名不同物**必须被机械检出：`{silver, spiritStones, secrets, clues}` 的 `name` 两两不同。
