---

## 一、这个区块解决什么问题

R4 之前，「洞天 4 处」和「势力 3 个」是两张**平铺的清单**：

- 它们之间没有位置关系，玩家从第一格就能直接挑战最深处；
- 攻伐是**零成本**的（不花任何资源），而占领**没有任何收益**——
  于是最优解是无脑连点，直到运气好为止。
- 界面只写「建议炼气三层」这种裸数字，玩家看不出该带谁去。

改完之后：

1. **节点摆成 4×2 的网格，相邻才能去**。想深入就得先打通沿途那一格。
2. **界面直接写建议境界、预估生还率、胜算百分比、镇守需求**。
3. **占领之后要派人镇守才有产出**，镇守不足会积累民怨直至叛离。
   所以「打下来」不再是终点，而是**维护成本**的开始。
4. 灵石多了一条**靠扩张获得**的稳定来源，与灵脉矿场并列。

百科条目直接取这一段，不要在百科里重抄一遍。

### 为什么产出的数字这么小

灵石是全局最紧的资源：四道突破门槛合计 1,200 灵石，
而灵脉矿场整个周目大约只能出 1,900 灵石。

如果领地赋税给得多（比如总计 0.5/秒），44 小时就是 79,000 灵石，
门槛会立刻失去意义。所以四个节点的产出**刻意压到合计 0.039/秒**
（满打满算约 3,400 灵石／周目），定位是「矿场之外的第二条腿」，
而不是取代矿场。

界面按 **灵石/时** 显示（3.6 / 10.8 / 36 / 90），因为 0.001/秒 这种数字玩家读不出量级。

## 三、抵达与解锁

```
踏入炼气篇  →  起点「青苔谷」自动抵达
探险成功 / 攻伐成功  →  该节点标记为「已抵达」
某节点可去  ⟺  它已抵达，或它的某个邻居已抵达
```

- **这是整张地图唯一的门槛**，实现上就是一个 `mapAccessible()`。
- 界面把去不了的节点整行压暗、按钮改成「未打通」，
  并在文案里直接说明原因（「与此地不相邻 · 需先打通沿途」）。
- 洞天没有「占领」的概念——探过就是探过；只有势力节点有占领状态。

## 四、镇守：把「打下来」变成维护成本

这是 R4 最重要的一次机制修正。

```
镇守需求 = 该节点战力 × 0.5
镇守战力 = 被指派修士的战力（含灵根带来的功法加成）

镇守充足  →  每秒产出赋税，民怨回落（1/300 每秒）
镇守不足  →  没有产出，民怨上涨（1/900 每秒）
民怨满 1  →  节点叛离，退回未占领状态
```

**设计意图**：

- **战力变成了双重资源**。原来战力只影响「打得过吗」，
  现在还要影响「守得住吗」。一个高战力修士是去前线还是去坐镇，是真取舍。
- **占领需要持续投入，不是一次性收益**。四个势力节点全部镇住需要
  55+280+1200+6000 = 7,535 战力，而一名炼气九层只有 549。
  所以打到后期，玩家必须在「继续扩张」和「守住已有」之间分配修士。
- **宗门的代价具体化了**：宗门修士不可镇守（他们不受家族调遣），
  所以「把天才送进宗门换灵石」会直接削弱你的守成能力。
  这是 R3 那条负面对价的第二重后果。
- **战败的折损也排除镇守者**——否则前线一败，后方就自动叛离，惩罚过重。

**民怨是个确定性计时器，不是随机事件。** 界面直接显示百分比，
玩家看到「民怨 47%（满则叛离）」就知道还有多久。随机夺走资产只会让人恼火。

## 五、与其它区块的接合点

| 区块 | 关系 |
|---|---|
| **洞天生还率**（R1 起） | 仍走 `caveSurvival()` 单一函数，面板预估／确认框／结算三处一致 |
| **灵根**（R3） | 洞天收益吃「涉险」道途（火灵根）、生还率吃「涉险」加成；修士战力含灵根功法加成 |
| **宗门**（R3） | 宗门修士不可探险、不可镇守，所以送人进宗门有隐性代价 |
| **百科**（R6） | 每个节点的 `lore` 就是百科条目正文 |
| **炼丹／炼器／炼符**（R5+） | 节点的 `yield` 目前统一是灵石；R5 起应当按节点类型产出**各自的材料** |
| **周目**（R11） | 「占领全部四个势力节点」是轮回条件之一的候选 |

## 六、存档迁移

旧存档的占领记录在 `cultivation.conquests`（一个字符串数组），
没有 `reached` / `garrison` / `unrest`。

- `hydrate` 显式构造 `cultivation.world`：`held` 缺失时**从 `conquests` 继承**
- `worldOf(state)` 幂等兜底：补齐字段、过滤非法 id、
  清掉指向未占领节点的镇守记录、**在玩家已有修士但 `reached` 为空时补上起点**
- 每帧结算后把 `world.held` 写回 `conquests`，所以**旧界面代码仍然能读**

> 保留 `conquests` 这个看起来冗余的字段，是为了让读它的旧代码不必一次性全改。
> 等界面完全迁移完就可以删掉。
