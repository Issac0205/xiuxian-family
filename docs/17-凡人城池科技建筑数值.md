## 一、锚点组落地：商道「探秘者 ↔ 稳健」（用户点名，写全）

### 1.1 确切科技定义

| 项 | 内容 |
|---|---|
| id | `steady` |
| 中文名 | **稳健** |
| 阶位 / 前置 | T4，`requires: ['trade']` —— 与 `seeker` 同层同前置，构成并列 |
| 成本 | **2200 银**【待校准】（`seeker` 为 1800；贵 400 = 「确定的钱」比「碰运气的消息」贵的溢价，推导见 1.4） |

均已接线。`formulas.tradeSecretChance()` 不动（稳健**不给任何秘闻加成**，用户硬要求）。

### 1.2 互斥决策：互斥，且必须先上 `requiresAny`

**决策：`seeker` ⊥ `steady` 互斥。** 理由（推演见 1.4）：

- 不互斥 = 严格占优合成解：探秘者的 −0.30 tradeIncome 被稳健的 +0.25 对冲大半
  （合成净赚 12→约 100 银/趟），6% 秘闻照拿，死亡税 +0.004 − 0.0003 仍在但
  银两侧近乎免费——「全都要」严格优于任一单选，直接违反筛子 1
  （合成后 tradeIncome = 1 − 0.30 + 0.25 = 0.95，净赚 = 100×1.6×0.95 − 100 = 52 银/趟，
  而单点探秘者只有 12 银/趟；+40 银/趟白捡，没有任何玩家有理由不全点）。
- 互斥的代价是 `yizhuang`（`requires: ['household','seeker']`）与仙道
  `lingmai`（`requires: ['seeker','zhenyue']`）会把选稳健的玩家永久锁在
  T6/仙道门外——**一条 T4 分支锁死 T6 与仙道科技，违反 `docs/15` §一支柱 3**。
  所以落地顺序是硬依赖：**先 `requiresAny` 机制，后互斥**（docs/16 风险 R1，本文采纳）。

### 1.4 二十小时解析推演（L1）

**速率常量与出处**：`MORTAL_ROUTE`：成本 100 银、`duration` 25 秒、
`multiplier` 1.6、`secretChance` 0.01（`src/data/trade.js`）；
单商队位 = 3600/25 = **144 趟/时**；净赚 = `routeProfit()` = 100×1.6×(1+tradeIncome) − 100。
开门门槛 `SECRET_UNLOCK` = 10 条，池 `SECRETS` 20 条不放回；
期望抽中次数按优惠券收集 = 20×(H₂₀−H₁₀) ≈ 20×(3.598−2.929) ≈ **13.4 次**（docs/16 §1.1）。
秘闻概率 = `tradeSecretChance()` = 0.01 + fx.secretChance + exploreTradeBonus；
**开门前无修士 ⇒ exploreTradeBonus = 0**（`systems/cultivation.js`，
`exploreTradeBonus = min(0.5, exploreUnits×0.02)`，explore 是修士职务）。
死亡口径：`BASE.deathRate` = 0.010/秒；`deathFlat` 全族叠加（`derive()`）。

**假设**：单商队位连续满负荷跑（玩家及时再派）；20 小时 = **2880 趟**；
不点其它 secretChance 科技（`jixian`/`xiangxian`/`jiexu` 均在开门之后，按解锁时点积分原则不计入开门前窗口）。

| 线 | 每趟净赚 | 开门期望趟数 | 开门时点 | 20h 商路净银（分段积分） |
|---|---|---|---|---|
| 不点分支 | 60 银 | 13.4/0.01 ≈ 1340 趟 | **≈ 9.3 h** | 2880×60 = **172.8k** |
| 探秘者（现状） | 100×1.6×0.7−100 = **12 银** | 13.4/0.06 ≈ 223 趟 | **≈ 1.6 h** | 2880×12 = **34.6k** |
| 稳健（本清单） | 100×1.6×1.25−100 = **100 银** | 13.4/0.01 ≈ 1340 趟 | **≈ 9.3 h** | 2880×100 = **288.0k** |

（分段积分说明：开门前后每趟净赚不变，秘闻池抽完后 secretChance 边际归零
——探秘者的 6% 是**纯开门加速器**，开门后它不给任何持续收益；
这正是它「买提前量」的定位，也是稳健能与之对峙的根本。）

**死亡一侧（按 20h 窗口积分）**：`deathFlat` 是全族速率，20h 总额外死亡
= deathFlat × ∫P(t)dt，取决于人口曲线，L1 给两个不变量锚点代替全曲线：

- 探秘者 +0.004 = `BASE.deathRate` 的 **+40%**，等价 **6.7 座演武台**
  （`ARENA_DEATH` = 0.0006）的死亡税；用出生对冲需 `FIELD_BIRTH`×n ≥ 0.004
  ⇒ **n ≥ 3.3，即 4 块田**（无 `tuntian`）才正好打平。选探秘者 =
  承诺把 4 块田（或等价的 `yizhuang` −0.0012 + 田）投进出账面。
- 稳健 −0.0003 = 抵偿 **0.25 块田 / 0.375 座驿站**（`CARAVAN_DEATH` = 0.0008），
  方向相反、量级刻意做小的防御性甜头。

**开门提前量的价值（探秘者买到的到底是什么）**：开门（10 秘闻）解锁
`CULTIVATOR_MARKET`（`planExchange` 的前提）与 `quzhang` 的研习资格
（`requiresSecrets`）。探秘者早 ≈7.7h 拿到这两张门票 ⇒ 首名修士的期望时点
早 ≈7.7h（丹钱另算，见 §六：首名修士期望 4 灵石 = 8 笔兑换 = 80 万银）。
修士侧的复利（探索/做工/投帖 `ERRAND_CLUE_PER_SEC`）从此多滚 7.7h——
这一段涉及修士产出曲线，**标【待校准】**，由 L2 仿真补；
L1 可锁定的是：7.7h ≈ 单商队位 1110 趟的商路窗口，探秘者用它换的是
「修士经济提前启动」，不是银两。

**稳健玩家的追开门手段（第二层取舍，健康）**：每多一座 `caravan` 多一路并行
1%：2 驿站开门 ≈ 4.6h、4 驿站 ≈ 2.3h。3 座增补驿站成本 ≈ 800+1024+1311 ≈ 3.1k 银
（`baseCost` 800 × `growth` 1.28^n）+ `CARAVAN_DEATH`×3 = +0.0024/秒死亡
+ 3 个营造格。稳健玩家拿银两（他的强项）换开门时间（他的弱项）——
**没有一条线严格占优**：

| 局面 | 谁明显更好 |
|---|---|
| 赶仙途速通、多周目、想早开炼气篇 | 探秘者（早 7.7h 拿门票） |
| 经营流、离线挂机多、人口长期顶住房软上限（死亡税最疼） | 稳健（20h 多 253k 银 − 少交死亡税） |
| 只玩前 2 小时就放置 | 探秘者（开门窗口内银两差只有 (100−12)×223 ≈ 19.6k，提前量主导） |
| 单商队位且不打算加盖驿站 | 稳健（9.3h 才开门，探秘者的提前量无法被摊薄） |

**选 A 失去什么**（筛子 1 的显式回答）：
- 选探秘者：失去 ≈253k 银/20h/商队位（288.0k−34.6k），背上 +40% 基础死亡率的税。
- 选稳健：失去 6% 秘闻（开门晚 7.7h/商队位），永远失去「1.6h 开门」这条速通路；
  追平要花银两盖驿站并吃 `CARAVAN_DEATH`。

**成本 2200 的推导**：探秘者 1800 买的是「7.7h 提前量 − 死亡税」；
稳健买的是「确定的钱」。同窗口银两差 253k 是 20h 累积量，科技定价不能照它定
（否则永远买不起），按同层科技带宽取：`seeker` 1800、`tuntian` 2200、
`trade` 2600 —— 稳健取 **2200**，与 `tuntian` 同档、低于 `trade`，
语义「T4 精进科技的标准价」。【待校准：三策略仿真若显示稳健选取率 <30%，
降至 2000；>70% 则升至 2400。】

## 一·附、科技树可见性门控（用户新规 · t5 实现契约）

> 用户原话：「玩家一进游戏看见好多未解锁科技其实是不太好的，建议只展示
> 下一阶段的科技……已解锁科技数/总科技数也不要显示。」
> 本节是程序负责人 t5 的**实现契约**，三条规则不可谈判；两个开放问题在此定掉。

### 三条硬规则

1. **只渲染 {已研习} ∪ {前置全部满足}**——其余科技不渲染（不是灰显，是不存在）。
   实现落点：`techStatus()` 之外的**可见性判定**（建议新函数 `isTechVisible(state, tech)`），
   UI 列表（格物页/参悟页）按它过滤；仙道侧 `isImmortalTechUnlocked()` 同理。
2. **研习后出现下一批**——规则 1 的自然推论：研习 `trade` 后 `seeker`/`steady`/`courier`
   这一批才浮现，「每次解锁都有新内容」。
3. **不显示已解锁数/总科技数**——UI 禁止出现「12/18」类计数；看到终点就是剧透。
   ⚠ 与规则 2 不冲突：进度感由「新一批科技浮现」本身提供，不由计数提供。

### 开放问题裁决（各一句理由）

- **占位策略：给。** 当可见集合为空（全部研习完或开局边界）时，显示一句
  **不泄露内容**的提示，如「山外还有未曾听过的风声。」——完全空白会让玩家
  误判「内容已尽 / 界面坏了」，一句无定语无计数的闲话既保神秘感又保「还有东西」的预期。
- **非科技前置：灰，不藏。** 科技前置未满足 ⇒ **藏**（暴露树形深度=剧透）；
  非科技门槛（`requiresSecrets`、`requiresImmortal`）未满足 ⇒ **灰显**并用
  现有缺口文案（如 `techStatus` 的「须集齐 N 条秘闻」）。理由：科技前置是
  「剧透」，而非科技门槛是**玩家当下就能为之努力的进度目标**（集秘闻是开门前的
  主线动作），藏起来等于删掉目标感。⇒ 可见性口径精确为：
  **`isTechVisible` = 已研习 ∨ 科技类前置（`requires` / `requiresAny`）全满足**；
  可见集合内再按 `techStatus()` 分 ready/open/locked（locked 即灰）。

### 与本文其余部分的衔接

- `excludes` 互斥锁定的科技**保持可见**（显示「已选他途」，§五）——它不是
  「未解锁」，是「已抉择」，藏掉会让玩家以为另一条路从未存在，破坏分支的重量。
- `terminal: true` 与分支端点（§五.1 豁免）同样只在科技前置满足后浮现。
- 计数类调试信息（`researchableCount()` / `researchableImmortalCount()`）属内部 API，
  不渲染到界面即合规。

## 二、分支点二落地：税赋「苛捐 ↔ 仁政」

### 2.1 确切定义

| | 苛捐 | 仁政 |
|---|---|---|
| id | `levy` | `benevolence` |
| 中文名 | 苛捐 | 仁政 |
| 阶位 / 前置 | T5，`requires: ['finance','household']`（与 `arithmetic` 同源同前置） | 同左 |
| 成本 | 3600 银【待校准】 | 3600 银【待校准】 |
| 效果 | `{ incomeMult: 0.18, birthFlat: -0.0004 }` | `{ incomeMult: 0.03, birthFlat: 0.0012 }` |
| 互斥 | **互斥**（`excludes` 互指）。理由：同一道国策的两面，且银两与人口共用
`derive()` 的 `silverPerSec` 乘数池（population × `BASE.silverPerPop` × (1+incomeMult+…)），
不互斥则合成解 incomeMult +0.21 / birthFlat +0.0008 严格优于 `arithmetic` 之外的一切组合 | 同左 |
| 新 effect 键 | 无（两键均已接线、有文案） | 无 |

### 2.2 推导与取舍

分支价值随**住房饱和度**切换（`CROWD.threshold` = 0.75，拥挤死亡
`CROWD.k`×over² 在占用率 75% 以上开始咬人）：

- **饱和前**（城还在长）：仁政占优。出生差 = +0.0016/秒（0.0012−(−0.0004)），
  人口 800 时 ≈ 每小时多 46 人进入产出池（0.0016×800×3600/100……精确：
  birthFlat 按人口比例，净增 ≈ 0.0016×800 = 1.28 人/秒量级 ⇒ 实际受死亡抵扣，
  粗锚每小时多 ~23 人【待校准】），这些人口立刻进 `BASE.silverPerPop` = 0.12
  的产出池并为作坊用工（`CITY_WORKSHOP_WORKERS`）供人。
- **饱和后**（住房顶死）：苛捐占优。incomeMult 差 = 0.15，
  人口 800 时 = 0.15×0.12×800 = **14.4 银/秒 ≈ 5.2 万银/时**；
  仁政的出生加成全部撞在拥挤上蒸发（`crowdDeath` 吃掉）。
- 选苛捐失去：饱和前的人口复利与作坊人手供给；
  选仁政失去：饱和后每秒 14.4 银（人口 800 口径）的纯收益。
- 这不是「前期 A 后期 B」的假分支：狂盖 `house` 撑容纳量的经营流仁政全程有用，
  营造格紧张、人口长期顶软上限的玩家苛捐是纯增益——**价值由玩家另一条线上的
  营造习惯决定**。

### 2.3 L2 验收

1. 互斥锁定（同 1.5.1/1.5.2 的形态）。
2. 注入 `state.techs` 含 `levy`、`state.population` = 800、住房饱和
   （`crowdOver` > 0）⇒ `derive(state).silverPerSec` 较无分支基准 +14.4 银/秒 ±1%。
3. 注入 `benevolence` + 人口 800 + 住房未饱和 ⇒ `derive(state).birthRate`
   较基准 +0.0012（×`schoolBirthMult` 口径）。
4. 孤儿规则：`levy`/`benevolence` 走 §三 的「分支端点豁免」，
   `auditTechs` 不报警。

| 中文名 | 三班倒 | 休耕 |

| 成本 | 8000 银【待校准】 | 8000 银【待校准】 |
| 效果 | `{ laborDeathMult: 2.0, cityMaterialMult: 0.40 }` | `{ laborDeathMult: -0.6, cityMaterialMult: -0.05 }` |
| 互斥 | **互斥**。不互斥则合成 laborDeathMult +1.4 / cityMaterialMult +0.35，
用 +0.35 材料白换一份可忽略的死亡率口径差异，违反筛子 1 | 同左 |
| 新 effect 键 | **`laborDeathMult`**（本轮唯一新键，登记位置见 3.3） | 同左 |

**为什么必须是新键（量纲陷阱，docs/16 的警告本文确认为硬约束）**：
`CITY_LABOR_DEATH` 只作用于**实际用工人数**
（`derive()` 的 `laborDeath = laborWorkers × CITY_LABOR_DEATH`），
而 `deathFlat` 作用于**全族**。用 `deathFlat` 模拟三班倒会误伤不做工的人
（人口 2000、用工 1000 时，等效死亡被放大 2 倍且落错人群）。
**决策：采纳推荐案（新键），不用兜底案。**

数值推导：用工 1000 人时现状折损 = 1000×1e-7 = 1e-4 人/秒 ≈ 0.36 人/时
（几乎无感，`docs/15` §3.3 的设计就是「咬得住咬不死」）；
三班倒 ×3 ≈ 1.1 人/时——相对人口 2000 时约 22 人/秒的自然出生仍「咬得住」，
但叠演武台/驿站/探秘者会把城推进「必须补田地」的状态。
材料一侧 cityMaterialMult +0.40 ≈ 白捡 0.8 项 `lingtian`（+0.50），
拿三倍折损去换。休耕 −0.6 ⇒ 折损 ×0.4 ≈ 0.14 人/时，材料 −0.05 是「象征性薄收」
【待校准：若仿真显示休耕选取率过低，把 −0.05 放宽到 0】。

### 3.2 选 A 失去什么

- 选三班倒：失去「人口安全垫」——任何其他死亡来源（探秘者/驿站/演武台）的
  边际伤害都被放大；且这条线在人口不足（`cityWorkersOf` 分摊）时价值骤降。
- 选休耕：失去 +0.40 材料——相当于放弃 0.8 项 `lingtian` 的供给，
  炼丹/炼器/画符的原料链全程薄一截。

### 3.3 新键 `laborDeathMult` 的三处清单（`docs/15` §七口径）

1. 累加器：**登记进 `MORTAL_EFFECT_KEYS`**（消费点是 `derive()` 的凡人侧结算，
   归凡人侧；不放进 `IMMORTAL_EFFECT_KEYS`——这是本文对 docs/16
   「由主策定」的裁决，理由：消费点决定归属，`laborDeath` 在 `derive()`）。
2. 文案：`EFFECT_LABELS` 增加 `laborDeathMult: (v) => \`作坊用工折损 ${signedPct(v)}\``。
3. 消费点：`derive()` 的 `laborDeath = laborWorkers × CITY_LABOR_DEATH × (1 + fx.laborDeathMult)`，
   下限 `Math.max(0, …)` 防负死亡。
   `scripts/smoke.mjs` 的两条对齐断言（键有文案、键被消费）会自动盯。

### 3.4 L2 验收

1. 注入 4 座 `herbhouse` + 人口 2000 + `overwork` ⇒ `derive(state).laborDeath`
   = 基准 ×3 ±1%，且 `expandDeath` 不变（证明只作用于用工口径，不误伤全族）。
2. 互斥锁定（同前形态）。
3. `cityMaterialMult` 双消费点核对：`derive()` 的 `cityHerbPerSec` 与
   `systems/immortal-economy.js` 的 `advanceCityWorkshops()` 读同一份 `fx`。

### 4.2 推导：期望严格相等，取舍在方差与预算奇偶

- 期望成本：quzhangdan = 1/0.25 = **4 灵石/修士**；wenbudan = 2/0.5 = **4 灵石/修士**。严格相等 ⇒ 不存在「更便宜」的严格占优。

  「这条明显更好」的局面**，筛子 1 通过。
- `planPill(state, pillId)` / `commitPill(state, pillId)` 已按 pillId 参数化
  （`engine.js`），数据表 `PILLS` 字段齐全，**不需要改数据结构**；

## 六、汇率平价化之后的总量评估（t3 已落地，本文评估其后果）

### 6.1 平价后的兑换参数（现状，工作区口径）

- 每笔：`MARKET_EXCHANGE_BASE_SILVER` = 100,000 银 →
  `MARKET_EXCHANGE_BASE_STONES` = 0.5 灵石 × (1 + tradeStoneMult)。
- **单价恒定** = 200,000 银/灵石 ÷ (1+tradeStoneMult)——平价化不改变单价，
  改变的是「每一笔的规模不再递增」。
- 总量闸门：`marketExchangeLimit()` = `MARKET_EXCHANGE_MAX`(12)
  + 4×(tradeStoneMult>0 的科技数)。全树这样的科技共 4 项：
  `marketexp`(0.25)、`mutualmarket`(0.35)（凡人）、`jiexu`(0.6)、`jielu`(0.4)（仙道）
  ⇒ 上限区间 **12 ~ 28 笔**。
- 报价永远 = 100k ≤ 银两上限（`BASE.silverCap` 3000 + `BANK_CAPACITY` 8000×钱庄，
  13 座钱庄或 6 座钱庄+`vault` 即破 10 万）⇒ 旧病「报价超上限、永远换不了」
  **在结构上消失** ✓（这是平价化最大的隐性收益，比兑率本身重要）。

### 6.2 全期可购灵石总量（按解锁时点分段，不全期乘速率）

tradeStoneMult 随科技推进升高，先换亏兑率、后换亏时间——这本身是个 pacing 决策。
两个极端情形（L1，假设：银两不构成约束——见 6.3，中后期成立）：

| 策略 | 计算 | 总灵石 | 总银两 |
|---|---|---|---|
| A. 解锁即换（贪心早换） | 12×0.5 + 4×0.5×1.25 + 4×0.5×1.6 + 4×0.5×2.2 + 4×0.5×2.6 | **21.2 灵石** | 280 万 |
| B. 攒到最后全换（m = 1.6） | 28×0.5×2.6 | **36.4 灵石** | 280 万 |
| C. 只换基础 12 笔（不点任何胃口科技） | 12×0.5 | **6 灵石** | 120 万 |

### 6.3 这个量对各境界节奏意味着什么

- **首名修士**：期望 4 灵石（`PILL_STONE_COST` 1 / `PILL_QI_CHANCE` 0.25）
  = 8 笔 = 80 万银。基础 12 笔 = 6 灵石 ⇒ **期望 1.5 名修士**——
  点火够用，但第二名修士开始就必须靠矿（`STONE_MINE_BASE_RATE`）。
- **第一项仙道科技 `kaimai`（12 灵石）**：超过基础闸门总量（6），
  不点 `marketexp`/`mutualmarket` 或不开矿就点不起——
  「坊市胃口科技」因此从「可选优化」变成「仙道主线的实质门槛之一」，
  与它们 T6/T7 的位置自洽 ✓。
- **全期占比**：仙道全树 stones 字段合计 ≈ **7815 灵石**
  （`IMMORTAL_TECHS` 逐项求和），兑换供给上限 36.4 = **0.47%**。
  ⇒ 平价化后的兑换是纯粹的**点火动脉**：它的全部意义在
  「首名修士 + 启动灵石矿场之前的那一段」，不是也不该是主灵石来源。
  这与 `config.js` 对 `STONE_MINE_BASE_RATE` / `SPIRIT_MINE_CITY_BONUS_PER`
  的定位一致，**方向正确**。
- **与旧递进制对比**：旧制 12 笔的总量 = Σ 0.5×1.2ⁿ ≈ **19.8 灵石**
  （Σ 100k×1.2ⁿ ≈ 396 万银，单价同样恒为 200k/灵石——旧制的「递进」递的
  是单笔规模，不是单价）。平价化把基础闸门总量从 19.8 砍到 6（−70%），
  换来「任何一笔都买得起」。**评估结论**：点火段（首名修士 4 灵石）仍被覆盖，
  但余量从 19.8−4 = 15.8 灵石压到 6−4 = 2 灵石，偏紧。
- **登记建议【待校准·待主策裁决】**：若希望保留旧制的点火余量，
  `MARKET_EXCHANGE_MAX` 12 → **24**：24×0.5 = 12 灵石，恰为 `kaimai` 门槛，
  语义「只靠兑换不开矿也能点火 + 开脉，但到此为止」。不调也成立
  （逼玩家早碰矿），两种取向都健康——这是口味问题，不是缺陷。本轮**不改**此常量（见 §八）。

发现的唯一系统性问题与科技侧同源：**营造没有任何「二选一」**
（每座都是「有钱就盖」），但营造的天然取舍已在「格位零和 + 死亡税 + 通胀」
三个机制里，**不主张为建筑再造分支**——分支化集中在科技层（§一~§四）即可。

## 十、非目标（本轮明确不改）

1. **不改 `MARKET_EXCHANGE_*` 任何常量**（含 §6.3 的 12→24 建议——登记待主策裁决，另开任务）。

   `tuntian` 摘 `requiresImmortal` 是提案（§七），待裁决后单独落地。

## 十一、风险登记与待校准清单

- **R1（硬依赖）**：`requiresAny` 机制必须先于互斥上线，否则 `yizhuang`/`lingmai`
  对稳健玩家永久锁死 = 新型软锁。落地顺序：机制 → `steady`+互斥 → 前置组改写。

  「分支是否严格占优」。分支上线前仿真需至少补一条「选稳健线」策略，
  否则 §1.4 的推演只能停在 L1。与 `docs/15` §八 欠账 4 同类。

  `isImmortalTechUnlocked()`，仙道树里的凡人分支 id 会查空——
  两处都是「不报错但错」的形态，smoke 应各加一条断言（§1.5.1、§1.5.5）。
- **待校准汇总**：`steady` 成本 2200（调档规则见 §1.4）；`levy`/`benevolence`

  12→24 建议；探秘者「修士经济提前 7.7h」的复利估值（需 L2）。
