---

## 一、这个区块解决什么问题

R7 是「炼丹 / 炼器 / 炼符」三体系的最后一块。
前两条线已经把**同构**的约定定下来了，所以这一轮的重点不是再发明一套结构，
而是回答一个问题：

> **符箓与丹药、法器有什么本质不同？**

| | 炼丹（R5） | 炼器（R6） | **炼符（R7）** |
|---|---|---|---|
| 成品性质 | **消耗品**，进突破门槛 | **长期资产**，加战力 | **「下一次行动」的加成** |
| 用在哪 | 冲关的那一刻 | 一直在身上 | 临出门前贴一张 |
| 负面对价 | 失败损失全部材料 | **耐久**（资产要养） | **保质期**（囤不住） |
| 归属性 | 木 | 金 | **火** |

所以炼符不是「第三个一样的系统」，而是补上了第三种时间尺度：
丹药是**一次性**的，法器是**长期**的，符箓是**短期**的。

## 二、符文：第三条并行的材料线

四种符文，产地仍是 R4 那四个势力节点 —— 与药材、矿料**同源但独立**。

| 符文 | 产地 | 产量 | 同节点的药材 / 矿料 |
|---|---|---|---|
| 符纸 | 青木寨 | 2.2 份/时 | 青灵草 / 灵木 |
| 朱砂 | 黑水门 | 1.6 份/时 | 寒潭菱 / 寒铁 |
| 灵墨 | 玄铁宗 | 1.3 份/时 | 玄铁芝 / 玄铁 |
| 妖血 | 万兽谷 | 0.7 份/时 | 赤焰花 / 妖骨 |

于是一个节点同时供三条线。**三条线的材料互不抢占**，
所以玩家不必做「这条线还是那条线」的排他选择 ——
真正的瓶颈始终是**领地与镇守战力**。

## 三、四张符箓

| 符箓 | 材料 | 基础率 | 需符台 | 效果 |
|---|---|---|---|---|
| 聚灵符 | 符纸×2 朱砂×1 | 80% | 1 | 全族修炼 **+30%**，持续 2 小时 |
| 护身符 | 符纸×2 妖血×1 | 62% | 2 | 下一次洞天生还率 **+20 个百分点** |
| 破阵符 | 灵墨×2 朱砂×2 | 48% | 3 | 下一次攻伐胜算 **+15 个百分点** |
| 冲关符 | 妖血×2 灵墨×3 | 30% | 4 | 下一次大境界突破成功率 **+12 个百分点** |

**四张符分别接在四个不同的决策点上**，而且每个决策点都已经存在：

- 冲关符 → R2 的 `breakthroughPlan`
- 护身符 → R1 起的 `caveSurvival`（唯一的生还率公式）
- 破阵符 → R4 的 `mapPlan` 攻伐胜算
- 聚灵符 → `progressCultivators` 的修为推进

所以炼符区块**没有新建任何一套机制**，它只是往已有的四个判断里各加了一项，
并且是可消耗的。

### 「下一次」的语义

护身符 / 破阵符 / 冲关符都是**挂一个待用加成**，等对应行动来消费：

```
useRune('chongguan')  →  pending.break = 0.12
breakthroughPlan()    →  rate = 基础率 + rootBonus + pending.break
commitBreakthrough()  →  consumePending('break')   // 无论成败都用掉
```

**无论成败都用掉**是刻意的：如果失败能保留，玩家就会「先用一张试试运气」，
符就退化成了免费重试。现在的语义是「我准备好了，这一把必须成」。

界面上，挂着的加成都写在符房的状态行里（`护身符 +20% · 冲关符 +12%`），
所以玩家不会忘记自己还有一张符没用。

## 四、保质期：炼符的负面对价

```
保质期 = 3 小时（游戏内时间）
补货不延长保质期 —— 先画的先过期
过期即整批作废（并写一条纪事）
```

**为什么这条对价是必需的**：如果符能无限囤，玩家会在开局一次性画一百张，
然后整个周目都不再回符房 —— 炼符就变成了一个一次性的前置工序，
而不是一条持续经营的线。

**为什么「补货不延长」是关键**：如果补货能刷新保质期，
玩家只要每隔两小时补一张就能把旧符永远保下来，
保质期就形同虚设。现在的规则让**存货量**和**新鲜度**成为一对真实的矛盾。

**离线也照常消耗保质期**（离线最多 12 小时，远超 3 小时），
所以挂着机回来不会白嫖一叠符 —— 这是有意的。

## 五、成功率（与炼丹、炼器同一条约定）

```
成功率 = 符箓基础率 + 符台加成 + 熟练度 × 1.5% + 火灵根加成
截断到 [5%, 98%]
符台等级在计算时夹到「至少该符的要求」
```

**火灵根加成**与前两条线完全对称：`0.08 + 0.04 × (灵根档位 − 1)`，
只有灵根里真的带火才算，天灵根火能到 +24%。

至此 R3 的五行全部有了归宿：

| 属性 | 归宿 |
|---|---|
| 木 | 炼丹成功率 |
| 金 | 炼器成功率 |
| **火** | **炼符成功率** |
| 水 / 土 | 功法道途（寻幽 / 经营） |

## 六、三个体系对照表（给后续加体系的人看）

| 环节 | 炼丹 | 炼器 | 炼符 |
|---|---|---|---|
| 数据文件 | `data/alchemy.js` | `data/forge.js` | `data/runes.js` |
| 规则文件 | `systems/alchemy.js` | `systems/forge.js` | `systems/runes.js` |
| 状态字段 | `cultivation.alchemy` | `cultivation.forge` | `cultivation.runes` |
| 主事职责 | `alchemy` | `forge` | `runes` |
| 灵根 | 木 | 金 | 火 |
| 设施 | `alchemyOf().furnace` | `forgeOf().level` | `runesOf().bench` |
| 熟练度字段 | `prof` | `prof` | `prof` |
| 询价 / 兑现 | `recipePlan` / `commitCraft` | `forgePlan` / `commitForge` | `runePlan` / `commitRune` |
| 升级 | `furnaceUpgradePlan` | `forgeUpgradePlan` | `benchUpgradePlan` |
| 调试出口 | `__xiuxian.alchemy` | `__xiuxian.forge` | `__xiuxian.runes` |

**要加第四条线（比如「阵法」），照抄这张表的一列即可。**
这是「每个区块方便修改」在实践中的样子。

## 七、已知待办

| 事项 | 说明 |
|---|---|
| **符箓没有纯战斗类** | 四张符都不直接加战力（战力归法器管）。可以加一张「爆体符」之类，但要小心数值膨胀 |
| **聚灵符不叠加时长** | 连用两张只延长到时点更晚的那一张，不会叠倍率也不会叠时长。这是防囤，但玩家可能误以为可以叠 |
| **`used` 计数只在探险里加了** | 攻伐与冲关消耗符箓时没有累加这个计数，将来做成就时要补 |
| **保质期的界面提示偏弱** | 只在存货标签上写了「2.4h」，没有临近过期的警示 |
| **三个面板结构高度重复** | 丹房 / 器坊 / 符房三块几乎一样，将来应当合并成一个「百工」页签加三个子标签 |

## 八、验证要点

`scripts/smoke.mjs` 里炼符相关的 57 项断言覆盖：

- 符文与药材、矿料的 **id 三方互不冲突**、都挂在真实节点上
- **四张符分别接在四个不同的决策点**上（`effect.kind` 去重后仍是 4 个）
- 越高级的符成功率越低、保质期为正
- 同一块领地**同时产三种材料**
- 画符：成功率四个来源（含天灵根火 +24%、无火不加成）、失败损失材料不涨熟练
- **保质期**：过期读数为 0、不能用、推进后被清掉并记日志、
  **补货不会把旧的洗成新的**
- 聚灵符：倍率 1.3、消耗一张、**真的加快了修为推进**、到期归 1
- 三张「下一次」符：**各自抬高对应决策点的数值**（冲关率 / 生还率 / 胜算），
  且**用掉即消耗**
- 符台升级、扣款、顶阶拒绝
- 三条线的**熟练度互不干扰**
