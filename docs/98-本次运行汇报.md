### 第 4 步为什么必须存在

本次运行开头，用户报「GitHub 上更新了内容但把我原有的东西删掉了很多」。

**真相是一个字都没删**：凡人科技线 18 条（含房地产）的 DOM 节点**全在**，只是被包在一个 `<div class="tech-list-static-placeholder" hidden>` 里 —— **永远看不见**。而当时 **805 项断言全绿**，因为**无头测试垫片根本不计算可见性**。

⇒ 由此建立了第 4 步：**真实浏览器里逐项检查"它是否真的可见"**，并配**阳性对照**（若检测函数恒返回 null，那条断言就是空的）。

**同一天，这一步又抓出两处同类缺陷**（`.manual-slots` 被 `hidden` 罩住、投帖入口根本不存在）。

### 第 5 步为什么必须存在

代码里有多处**手写的字段白名单**（`serialize()` 顶层 23 键、`hydrate()` 的逐人白名单、`repairCultivation()` 的家族级白名单）。**漏一个字段 = 玩家刷新一次就静默丢档**，而且**不报错**。

本轮实测发现过：`immortalTechs` / `morality` / `exchangeCount` 三个顶层字段、以及逐人的 `errandSince` —— 全都会在读档时静默消失。

⇒ 第 5 步用一份 **198 个 id 的基线**逐一比对，任何解锁内容丢失都会红。

## 五、这次运行建立的**机制**（比功能更不容易被看见，但更重要）

### 1. 放行门：把「我问过了」变成「机器验过了」
推送权收归单点，`release.mjs` 六步缺一不可。**它不是形式** —— 今天两次真实事故（整条科技线不可见、投帖入口不存在）都是在**断言全绿**的情况下差点推上去的。

### 2. 断言的三条轴

| 轴 | 盲区 | 实例 |
|---|---|---|
| **分派口** | 只查数据表/文案 ⇒ **分派错档一路绿穿** | 成率轴只覆盖了三分之一 |
| **话术口** | 只查 `ok === false` ⇒ **话术退化测不到** | 三处「拒绝理由点名」缺失 |
| **时序口** | 取样前先 `render()` ⇒ **瞬态不一致测不到** | `data-errand-count` 在"勾选→未渲染"窗口里滞后 |

### 3. 「看起来验过了」是全项目最稳定的失效模式

一天里，团队四个人各自独立踩中并抓出一次。统一表述是两句话：

> **一条检查必须能回答「它凭什么会失败」。**
> **它测的对象，必须是它声称要测的那个。**

具体形态包括：一条恒为空数组的校验（`&& false`）、用**内容差异**判**提交数**、只查数据表不查实现真正读的入口、**同一个脚本 36 秒内结论翻转**（被测产物在窗口内被队友重建）。

### 4. 多 agent 共用仓库的纪律
- 提交必须**路径受限**（`git commit -F <msg> -- <paths>`），且**提交前用未过滤的 `git diff --cached --name-only` 确认**
- **绝不 `git add -A`**、**绝不 force push**；分叉用 `merge` 解决（两侧历史都保留）
- 判「有没有待推送」用**提交数**，不能用内容差异

### 5. 工作区快照
用**临时 git 索引**拍快照 —— 全程不碰工作区、不碰真实索引、不移动 HEAD，**所以成员正在改代码时也能安全运行**。回退前会先自动快照当前状态，**让"回退"这个动作本身也可回退**。

## 六、本次运行的一件事，我认为值得单独写下来

**团队里有人拒绝照字面执行一条指错了地址的指令。**

我给监管者的指令是「把某条判据写进 `longtask-and-diagnostics.md` 的 R8」。它核对后发现**那个文件的 R8 是「执行策略」**（PowerShell 那节），于是：

1. **没有照字面执行** —— 去了主题相符的那个文件；
2. **顺手纠正我另外两处记忆错位**；
3. **把我记错这件事写进了规则本身** —— 否则下一个人会照着同一个错误编号再找一次，然后以为那条判据不存在。

> **一条指错地址的指令，应该被核对并归位，而不是被照办。**

当天团队栽的跟头里有一大半是这句话的反面：照注释找不存在的函数、照旧验收标准判正确的实现、照陈旧的本地引用判"有没有推送"、照 `git status` 判"有没有装东西"。
