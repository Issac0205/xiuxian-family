## 零 · 这份文档回答什么

用户原话（逐字）：

> 另外我们的通商玩法太单薄了 ……（`docs/96 §零` 已逐字留档）

**本质是挂机领奖励，与修仙世界观不符** —— 所以整条删掉，换成**寻仙探索**：
**遣族人出门打探，回来带回秘闻**（凡人接触仙道的唯一桥梁）、少量银两与见闻。

**一句话结论先行**：

## 二 · 三条不能破的语义

### 2.1 🔴 派出去的人必须留 1 个凡人在族中

`planExpedition` 里：

```
if (state.population - def.people < 1) return { ok:false, reason:`需留 1 人在族中：…` };
```

**这条是硬守卫，不是提示**。凡人人口是指数增长的底数（`derive().birthRate × state.population`），
把人口派到 0 之后**没有任何机制能把它长回来** —— 那不是惩罚，那是**死局**。

批量派遣（`expeditionFleetSize`）另有一重同名约束：`byPeople = floor(max(0, population − 1) / def.people)`，
即「整批派完之后仍留 1 人」。

**边界也验了**：人口 6、青山访闻要 5 人 ⇒ 6 − 5 = 1，**允许**。守卫不许写成「一律拒绝」。

### 2.2 秘闻没有总量上限

`SECRETS`（文本池）只有 20 条，而**三道门**要 10（坊市）/ 15（寻龙尺）/ 20（抽干池）。
`grantSecret` 在池子抽干之后**仍然 `cultivation.clues += 1`**（这是既有实现，`core/engine.js` 的注释写着为什么）。
探索继承这条口径：**池空 ≠ 收益断供**。

断言：`st.secrets` 摆成 20/20 之后，归来一次仍然 `clues` 0 → 1，且 `secrets.length` 仍是 20。

### 2.3 时间按**游戏秒**记账

`expeditions[]` 元素存的是 `remaining / total`（游戏秒），**不存绝对时间戳**——
所以中途改倍速时，剩余时间与进度条会自然跟着变，不必回头重算。
这条口径是从原商队**原样继承**的（它是对的），`docs/97-修士命名与离线.md` 的离线口径也一并沿用。

⚠ 但**故意去掉了一层加速**：原 `routeSeconds()` 会乘 `(1 − fx.tradeSpeed)`，
而 `expeditionSeconds()` **恒等于 `def.duration`**。理由：探索的收益是秘闻，
加速等于把 10/15/20 三道门**直接放闸**（见 `systems/expeditions.js` 的文件头注释）。
要调快慢就改 `data/expeditions.js` 的 `duration`。

## 三 · 存档 v2 → v3

```
SAVE_MIGRATIONS = { 1: migrateV1toV2, 2: migrateV2toV3 }
```

- `migrateV1toV2`（I0 起就在）：`tradeRuns` → `expeditionRuns`（**保留** `tradeRuns`）
- `migrateV2toV3`（本轮）：
  1. `caravans` → `expeditions`，元素键 `routeId` → `id`，并**删掉 `caravans`**
  2. `tradeRuns` → `expeditionRuns`（若还没有），并**删掉 `tradeRuns`**

### 3.1 ⚠ 在途的商队一个都不许丢（本迁移唯一有风险的资产）

旧商路只有 **一个 id**：`mortal`（`data/trade.js` 的 `MORTAL_ROUTE`）。
它在新地点表（`EXPEDITION_MAP`）里**没有对应项**，直接搬过去会被 `hydrate` 的
`.filter(e => EXPEDITION_MAP[e.id])` **静默过滤掉** ⇒ 玩家已经付掉的盘缠与等掉的时间白费。

所以迁移里**折算**：

```
const want = (typeof c.id === 'string') ? c.id : c.routeId;
const id   = EXPEDITION_MAP[want] ? want : 'qingshan';   // 同量级的一趟探索：青山访闻
```

- 已经是合法地点 id 的（理论上不会有，但允许）原样保留；
- 其余一律折算成 `qingshan` ⇒ **不存在「某一趟被静默丢弃」这条路径**；
- 旧商队没有「派了几个人」这一项 ⇒ 按该地点的标准人数补上（`EXPEDITION_MAP[id].people`，
  否则归来结算的折损会算在 0 人头上）。
  **副作用（如实说）**：折算之后玩家会**白得**几个人的返还（最多 5 人，还要过 2% 折损）。
  这是刻意选的方向：宁可白送几个人，也不能白吞一趟。

⚠ `migrateV2toV3` 里那个三元表达式是**承重的**：`people: num(c.people, EXPEDITION_MAP[id].people)`
只有在 `id` 一定合法时才是安全的。不要把它简化成 `want`。

### 3.2 兼容分支只许住在迁移里

`hydrate()` 里**没有** `raw.caravans ?? …` 这类分支（`docs/101` 与 `save.js` 的既有约定：
迁移是一次性的、读档路径是每次的；兼容分支写进 `hydrate` 就再也没人敢删）。
`hydrate` 只读 `raw.expeditions`，`people` 缺失时按该地点标准人数兜底（这是**默认值**，不是别名兼容）。

## 四 · 数据表 id 纪律

- `buildings.js` 的 `caravan`：**id 不动**，只改显示名「驿馆」。存档里存的是 `buildings.caravan`。
- `trade.js` 的 `MORTAL_ROUTE.id = 'mortal'`：**保留**（基线与老档都认得它），但**已无调用方**。
- 注册表（`data/resources.js`）的三个 id **改了名**（`tradeRuns → expeditionRuns` 等）。
  ⚠ 这里与 `docs/101 §1.2`「注册表 id 永不重命名」的**字面**约定有张力，如实记一笔：
  - 注册表 id **不进存档、不进 `serialize()`**（`docs/101 §1.1` 明写「不是存档结构的一部分」）；
  - `scripts/savecompat.mjs` 的基线只扫 `src/data/*.js` 里 `id: '…'` 的**字面量**，注册表用的是
    `makeResource('…')` 位置参数，**扫不到**；
  - 所以这次改名**没有老档风险**，但**违反的是文档约定而不是代码安全**。若主策认为该约定必须守，
    下一轮把它们改回去即可（无迁移成本）。
