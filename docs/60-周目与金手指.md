# 区块设计：周目与金手指

> 上位文档：`00-整体策划.md` §4.8
> 对应源码：`src/data/reincarnation.js`（表）、`src/systems/reincarnation.js`（规则）
> 状态：**已落地**（R9）

---

## 一、这个区块解决什么问题

一个 44 小时的挂机游戏，跑到化神之后还剩什么？如果答案是「继续挂」，
那么这一局的结尾就是下一局的开头，玩家没有理由重来。

周目系统要回答的是：**为什么要再走一遍，以及第二遍凭什么不一样。**

答案是两条：

1. **轮回点**——把这一局的成就折算成一种跨局的货币
2. **金手指**——用轮回点买下**改变规则**的东西

---

## 二、核心原则：金手指改变规则，不是数值

这是 R1 就定下的原则，也是这一区块唯一重要的设计决定。

**反例**（不做）：「灵石产出 +50%」。这是数值膨胀——第二周目就是
同样的游戏，数字大一点。玩家玩到第三遍就腻了。

**正例**（做）：**掌天瓶**。它不是一个乘数，而是**一个第一周目里不存在的做法**：
别人的药材产量是固定的，你的可以涨。它让第二周目的**玩法**不同，
而不只是速度不同。

四件金手指，每件都配一个代价：

| 金手指 | 改变了什么规则 | 代价 |
|---|---|---|
| **掌天瓶**（韩立的小绿瓶） | 药材 / 矿料 / 符文产出 **×2.5** | 全族修炼速度 **−10%** |
| **戒中老者** | 冲关成功率 **+12 个百分点** | 每次冲关成功后**额外消耗一枚同阶丹药** |
| **前世记忆** | 开局即解锁 3 项科技，已知晓 2 处地点 | 答题带来的增益**减半** |
| **气运加身** | 洞天生还率 **+15 个百分点** | 灵石产出 **−20%** |

**「每件都必须有代价」是硬约定**，冒烟测试里有一条专门盯着它
（`fgs.every(f => f.price && f.price.length > 8)`）。没有代价的金手指
会让轮回退化成纯粹的数值膨胀——那正是这一区块要避免的东西。

而且代价都**咬在别的体系上**：掌天瓶咬修炼、戒中老者咬丹药、
气运加身咬灵石。所以带了金手指之后，玩家的最优策略会**真的改变**：
带掌天瓶就该多占地、少闭关；带气运加身就该多下洞天、少指望赋税。

## 三、轮回门槛

```
修至 化神初期（realmIndex 22）即可轮回
```

**为什么是化神初期而不是圆满**：圆满要跑满 44 小时。轮回的意义是「再来一局」，
让人在 26 小时左右就能选择重开，比逼他跑完更尊重他的时间。
想跑满的人可以继续跑，选择权交还给玩家。

### 轮回点结算（看得见的算式）

```
轮回点 = 1（基础）
       + 已占领领地数 × 1
       + 已收录功法数 ÷ 5（向下取整）
       + 最高境界每高出化神初期 1 级 × 1
```

刻意做成**界面上逐项列出来**的形式。玩家应当能预期「我多占一块地能多拿一点」，
而不是面对一个黑箱。

## 四、重置要保住什么（这一区块最危险的迁移点）

轮回是全篇唯一会**销毁玩家进度**的操作。所以保留名单必须显式写出来，
并且逐项有测试：

```js
const REINCARNATION_KEEP = ['meta','settings','quiz','wordStats','customQuizStats','customWrongBooks','ui'];
```

| 保留 | 为什么 |
|---|---|
| `meta` | 元进度本身。不保留就等于没有周目系统 |
| `settings` | 难度、答题频率、倍速——这是偏好不是进度 |
| **`quiz` / `wordStats` / `customQuizStats` / `customWrongBooks`** | **答题的学习记录。英语单词的掌握程度不该因为重开而清空** |
| `ui` | 买法、折叠状态等界面偏好 |

> 最后那一条尤其要想清楚。这个游戏的答题部分是**真实的六级词汇学习**，
> 玩家答对的每一道题都是他的学习成果。如果重开一次就把错题本清空，
> 那是在惩罚玩家重开，也是在毁掉这个游戏最有实际价值的部分。

**另一个坑**：`createState()` 只给骨架，丹房 / 器坊 / 符房 / 地图世界
都是惰性初始化的（第一次调用 `alchemyOf()` 之类才建）。所以重置之后
必须补一次 `repairCultivation(state)`，否则新周目的头几帧会读到 `undefined`。
这个 bug 被测试抓到了（`Cannot read properties of undefined (reading 'furnace')`）。

## 五、解锁与携带分离

```
解锁：花轮回点，永久
携带：从已解锁里挑，最多 2 件，免费
```

**为什么分开**：如果携带也要花点数，玩家每局都要重新付费，
金手指就变成了消耗品而不是积累；如果解锁和携带是一回事，
那「最多 2 件」就毫无意义（解锁了几件就带几件）。

分开之后：

- **轮回点是投资**：花 3 点买下掌天瓶，以后每一局都能用
- **携带位是取舍**：解锁了四件但只能带两件，所以每一局开局都要重新选

这个取舍才是周目的玩法所在。

## 六、效果出口

其它区块**不直接读 `meta`**，只调这几个函数：

| 函数 | 接在哪 |
|---|---|
| `metaMaterialMult(state)` | `advanceTerritories` 的药材 / 矿料 / 符文产出 |
| `metaStoneMult(state)` | 同上的灵石产出 |
| `metaTrainMult(state)` | `progressCultivators` 的修为推进 |
| `metaBreakBonus(state)` | `breakthroughPlan` 的冲关成功率 |
| `metaSurvivalBonus(state)` | `caveSurvival`（唯一的生还率公式） |

多个金手指改同一项时会叠加：倍率类相乘、加法类相加。

## 七、接合点

| 区块 | 关系 |
|---|---|
| **境界**（R2） | 化神初期是轮回门槛；`realmName` 用于结算展示 |

## 八、已知待办

| 事项 | 说明 |
|---|---|
| **只有四件金手指** | 目标说「一些比较经典的金手指」，四件偏少。可以再加「系统面板」「随身空间」之类 |
| **没有周目专属成就** | 比如「某一世不杀一人」「三世皆至化神」，能大幅提升重开的动力 |
| **金手指不能中途更换** | 只能在轮回时选。做成「一世可换一次、代价是扣点」会更有张力 |
| **结算公式里没有时间维度** | 跑得快没有额外奖励，可以加「以更短时间达成则加成」 |
| **`history` 只存了 20 条** | 且没有展示曲线。将来可以做一张「历世最高境界」的小图 |
| **重置没有二次确认的强度分级** | 现在是一次 `confirm`。这是不可逆操作，也许该让玩家手输「轮回」二字 |

## 九、验证要点

`scripts/smoke.mjs` 里轮回相关的 63 项断言覆盖：

- **每件金手指都有正面规则、代价、背景文字、效果数值**（四条硬约定）
- 掌天瓶确实在表里（目标点名要的）
- 门槛：境界不够时拒绝、理由点明还差多少；修至化神即可
- 结算：四项明细之和 = 总点数；多占一块地就多一点
- 解锁：点数不足拒绝、扣点数、重复解锁拒绝、未解锁不能携带、
  **超过携带位拒绝**、不存在的 id 被过滤
- **效果真的接进去了**：不带时全部中性；掌天瓶让药材产量实测 ×2.5、
  同时实测拖慢修炼；戒中老者让冲关率 +12 个百分点；气运加身让生还率 +15 个百分点
- **重置要保住什么**：家业 / 科技 / 修士 / 功法 / 领地 / 丹房 / 器坊 / 符房全清，
  而**答题记录、设置、已解锁金手指、历世记录**全留
- 前世记忆的开局效果（科技与已知地点）
- 界面：卡片渲染、chip、代价文案、点击解锁与携带
